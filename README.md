# Swift package export Release-link reproducer

Minimal standalone reproduction for [KT-90738](https://youtrack.jetbrains.com/issue/KT-90738) using Kotlin 2.5.0-Beta2: a Swift package generated by Kotlin Swift export links in an Xcode Debug build but fails in Release with an undefined `KotlinRuntimeSupport_linkAnchor` symbol.

This project contains only a tiny Kotlin library, a generated local Swift package, and a minimal iOS app target.

## Requirements

- macOS with Xcode 27.0 (27A266a) and XcodeGen 2.46.0
- JDK 17 or newer; the recorded run used JDK 21.0.12.1
- Gradle 9.7.1 (provided by the checked-in wrapper)
- iOS 18 or newer deployment target

This reproducer exercises Kotlin 2.5.0-Beta2 Swift package export using a local
package. Beta2 supports using `swiftPackageIntegration()` alongside
`xcodeIntegration {}`, requires iOS 18 or macOS 15 or newer, and does not yet
support combining Swift package export with Gradle's `swiftPMDependencies {}`.
This minimal case has one exported Kotlin module and does not cover multi-module
exports. The official Kotlin sample demonstrates both Xcode integration and a
multi-module Swift package consumer: [Kotlin/swift-export-sample#5](https://github.com/Kotlin/swift-export-sample/pull/5).

## Reproduce

Generate the Swift package and the Xcode project:

```sh
./gradlew :shared:exportDebugSwiftPackage :shared:exportReleaseSwiftPackage
xcodegen generate --spec consumer/project-debug.yml
```

Build Debug against the Debug package:

```sh
xcodebuild -project consumer/SwiftPackageExportRepro.xcodeproj \
  -scheme SwiftPackageExportRepro -configuration Debug \
  -destination 'generic/platform=iOS Simulator' ARCHS=arm64 \
  CODE_SIGNING_ALLOWED=NO build
```

Switch the generated Xcode project to the Release package and build Release:

```sh
xcodegen generate --spec consumer/project.yml
xcodebuild -project consumer/SwiftPackageExportRepro.xcodeproj \
  -scheme SwiftPackageExportRepro -configuration Release \
  -destination 'generic/platform=iOS Simulator' ARCHS=arm64 \
  CODE_SIGNING_ALLOWED=NO build
```

## Expected result

Both configurations should link the app against the generated Swift package.

## Observed result

On macOS 27.0.1 (arm64), Xcode 27.0 (27A266a), JDK 21.0.12.1, and Gradle 9.7.1:

- `:shared:exportDebugSwiftPackage` and `:shared:exportReleaseSwiftPackage` both succeed.
- The Xcode Debug build against `shared/SwiftPackage/Debug` succeeds.
- The Xcode Release build against `shared/SwiftPackage/Release` failed in three earlier runs using separate, clean DerivedData directories and reproduced again in a fresh clean DerivedData directory on 2026-10-26:

```text
Undefined symbols for architecture arm64:
  "_KotlinRuntimeSupport_linkAnchor", referenced from:
      _KotlinRuntimeSupport_ensureLinked in libComposablesKotlin.a[...]
ld: symbol(s) not found for architecture arm64
clang: error: linker command failed with exit code 1
```

Setting `DEAD_CODE_STRIPPING=NO` did not resolve the Release linker failure. No workaround is confirmed. The project is deliberately a single exported module to keep the reproduction small; multi-module export is not covered by this minimal case.

## Versions

The Kotlin Gradle plugin version is pinned in `gradle.properties`. The generated XCFramework and package are build outputs and are intentionally not committed.

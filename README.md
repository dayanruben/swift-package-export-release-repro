# Swift package export Release-link reproducer

Minimal standalone reproduction for [KT-90738](https://youtrack.jetbrains.com/issue/KT-90738) using [Kotlin 2.5.0-Beta2](https://github.com/JetBrains/kotlin/releases/tag/v2.5.0-Beta2): a Swift package generated by Kotlin Swift export links in an Xcode Debug build but fails in Release with an undefined `KotlinRuntimeSupport_linkAnchor` symbol.

This project contains only a tiny Kotlin library, a generated local Swift package, and a minimal iOS app target.

## Requirements

- macOS with Xcode 27.0 or newer and XcodeGen 2.46.0; the latest
  confirmation used Xcode 27.2 (27B52)
- JDK 17 or newer; the original three Release failures used JDK 21.0.12.1,
  and the 2026-10-26 confirmation used JDK 21.0.11
- Gradle 9.7.1 (provided by the checked-in wrapper)
- iOS 18 or newer deployment target

This reproducer exercises Kotlin 2.5.0-Beta2 Swift package export using a local
package. Beta2 supports using `swiftPackageIntegration()` alongside
`xcodeIntegration {}`, requires iOS 18 or macOS 15 or newer, and does not yet
support combining Swift package export with Gradle's `swiftPMDependencies {}`.
This minimal case has one exported Kotlin module and does not cover multi-module
exports. The official Kotlin sample demonstrates both Xcode integration and a
multi-module Swift package consumer: [Kotlin/swift-export-sample#5](https://github.com/Kotlin/swift-export-sample/pull/5).

## Reproduce

Generate the Swift package and the Xcode project:

```sh
./gradlew :shared:exportDebugSwiftPackage :shared:exportReleaseSwiftPackage
xcodegen generate --spec consumer/project-debug.yml
```

Build Debug against the Debug package:

```sh
xcodebuild -project consumer/SwiftPackageExportRepro.xcodeproj \
  -scheme SwiftPackageExportRepro -configuration Debug \
  -destination 'generic/platform=iOS Simulator' ARCHS=arm64 \
  CODE_SIGNING_ALLOWED=NO build
```

Switch the generated Xcode project to the Release package and build Release:

```sh
xcodegen generate --spec consumer/project.yml
xcodebuild -project consumer/SwiftPackageExportRepro.xcodeproj \
  -scheme SwiftPackageExportRepro -configuration Release \
  -destination 'generic/platform=iOS Simulator' ARCHS=arm64 \
  CODE_SIGNING_ALLOWED=NO build
```

## Expected result

Both configurations should link the app against the generated Swift package.

## Observed result

On macOS 27.0.1 (arm64), Xcode 27.0 (27A266a), Kotlin 2.5.0-Beta2,
Gradle 9.7.1, and XcodeGen 2.46.0:

- `:shared:exportDebugSwiftPackage` and `:shared:exportReleaseSwiftPackage` both succeed.
- The Xcode Debug build against `shared/SwiftPackage/Debug` succeeds, including
  the fresh JDK 21.0.11 run.
- The Xcode Release build against `shared/SwiftPackage/Release` failed in five earlier attempts (three with JDK 21.0.12.1 and two with JDK 21.0.11). It failed twice more on 2026-10-27 with Temurin 21.0.12.1, each using a separate clean DerivedData directory:

```text
Undefined symbols for architecture arm64:
  "_KotlinRuntimeSupport_linkAnchor", referenced from:
      _KotlinRuntimeSupport_ensureLinked in libComposablesKotlin.a[...]
ld: symbol(s) not found for architecture arm64
clang: error: linker command failed with exit code 1
```

Setting `DEAD_CODE_STRIPPING=NO` did not resolve the Release linker failure. No workaround is confirmed. The project is deliberately a single exported module to keep the reproduction small; multi-module export is not covered by this minimal case. The two additional Release failures were reproduced with separate clean output directories and Temurin JDK 21.0.12.1.

Additional confirmation on 2026-10-31 used macOS 27.2 (arm64), Xcode 27.2
(27B52), Temurin JDK 21.0.12.1, Gradle 9.7.1, and XcodeGen 2.46.0. Both
Swift package export tasks again succeeded and produced `Package.swift`, the
generated Swift sources, and the XCFramework. The Xcode Debug consumer build
passed. The Release consumer build failed twice more, each with a separate
clean DerivedData directory, at the same undefined
`_KotlinRuntimeSupport_linkAnchor` symbol. Through this run, Release linking
failed in 11/11 clean attempts. No workaround is confirmed.

Further confirmation on 2026-11-01 used macOS 27.2 (arm64), Xcode 27.2
(27B52), Swift 6.4.2, Temurin JDK 21.0.12.1+1, Gradle 9.7.1, and XcodeGen
2.46.0, with an iOS 18.0 deployment target. The Debug consumer link passed.
Two additional Release consumer builds, each using a separate clean DerivedData
directory, failed with the same undefined `_KotlinRuntimeSupport_linkAnchor`
symbol at the iOS Simulator arm64 link step. Across all recorded clean
attempts, Release linking failed in 13/13 runs. No workaround is confirmed.

## Versions

The Kotlin Gradle plugin version is pinned in `gradle.properties`. The generated XCFramework and package are build outputs and are intentionally not committed.
